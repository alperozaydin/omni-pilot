# Omni Pilot — Micronutrient Analysis (v1)

## Purpose

Analyze daily micronutrient intake from MacroFactor food logs, compare against WHO/NIH recommended ranges, and surface deficiencies or excesses. This is the first module of a broader nutrition + workout analysis application.

## Problem

MacroFactor tracks calories and macros well, but micronutrient tracking is incomplete — most foods in the log have partial or no micro data. The user wants to know: "Am I getting enough of each vitamin, mineral, and essential amino acid on a daily average basis?"

## Key Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Micro data source | USDA FoodData Central only | Most comprehensive micro profiles. MacroFactor micro data is partial and inconsistent — mixing sources creates confusion |
| What we use from MacroFactor | Food names, serving weights (g), dates, macros | These are reliable; MacroFactor's core purpose is macro tracking |
| German product handling | Manual mapping file (user maps to English generic equivalents) | Automated translation is unreliable; user knows best what they ate |
| Food micro cache | TinyDB (JSON-backed document DB) | Inspectable like JSON, but with query API; no external DB server |
| Reference ranges | Pre-populated YAML with NIH/WHO values | Already created at [`config/reference_ranges.yaml`](file:///Users/seric/Projects/omni-pilot/config/reference_ranges.yaml) — configurable demographics |
| Daily calculation | Simple average across all logged days | Good enough for v1; no filtering of incomplete days |
| Unit system | Grams only | MacroFactor treats ml ≈ g for liquids; error margin (~3%) is negligible for nutrition analysis |
| Cross-validation | Dropped | MacroFactor micro data is reliable when present but incomplete; OpenFoodFacts has the same gaps. Using a confidence flag instead |
| Output | Rich CLI (primary) + optional HTML report | Terminal for daily use, HTML for reference/sharing |

## Module Specifications

### 1. Parser (`parser.py`)

**Input:** MacroFactor `.xlsx` file path

**Reads:** "Food Log" sheet only (for v1)

**Output:** List of `FoodEntry` dicts:
```python
{
    "date": "2026-07-13",
    "time": "12:29",
    "food_name": "Boiled Eggs",
    "serving_size": "extra large",
    "serving_qty": 3.0,
    "serving_weight_g": 56.0,      # weight of ONE serving unit
    "calories_kcal": 260.0,
    "protein_g": 21.0,
    "fat_g": 18.0,
    "carbs_g": 2.0,
}
```

**Key behavior:**
- Computes `total_weight_g = serving_qty × serving_weight_g` for each entry
- Skips entries where `food_name` is `None`
- Logs a warning for "Quick Add" entries (no real food to look up)
- Extracts unique food names for the mapping file

**Side effect of `import` command:** Generates `config/food_mappings.yaml`:
```yaml
# Generated by: python -m omni_pilot import
# Fill in the USDA-searchable English name for each food.
# Set to "skip" for foods to exclude from micro analysis.
# Leave empty and re-run import to see which foods still need mapping.
mappings:
  "Bergbauern Käse, Würzig-Nussig": ""
  "Boiled Eggs": ""
  "Haferflocken": ""
  "Hähnchen-Minutenschlitzel": ""
  "Quick Add": "skip"
  # ... all unique food names, sorted alphabetically
```

If `food_mappings.yaml` already exists, the import command **merges** — adds new foods, preserves existing mappings.

### 2. Enricher (`enricher.py`)

**Input:** Food name (English, from mapping) + TinyDB instance

**Data source:** [USDA FoodData Central API](https://fdc.nal.usda.gov/api-guide)
- Endpoint: `https://api.nal.usda.gov/fdc/v1/foods/search`
- API key: free, register at [api.data.gov](https://api.data.gov/signup/)
- Preferred datasets: "SR Legacy" and "Foundation Foods" (most complete micro profiles)

**Flow:**
1. Check TinyDB for cached entry by food name
2. If cached and not stale → return cached micro profile
3. If not cached → query USDA API with English food name
4. Pick the best match from results (prefer SR Legacy / Foundation datasets)
5. Extract per-100g micro values for all tracked nutrients
6. Store in TinyDB with metadata

**TinyDB record:**
```json
{
    "original_name": "Haferflocken",
    "usda_query": "rolled oats",
    "usda_name": "Cereals, oats, regular and quick, not fortified, dry",
    "usda_fdc_id": 168872,
    "usda_dataset": "SR Legacy",
    "per_100g": {
        "vitamin_a_mcg": 0,
        "vitamin_c_mg": 0,
        "calcium_mg": 54,
        "iron_mg": 4.72,
        "zinc_mg": 3.97,
        "magnesium_mg": 177,
        "...": "all nutrients from reference_ranges.yaml"
    },
    "confidence": "mapped",
    "last_updated": "2026-08-09"
}
```

**Confidence levels:**
- `"direct"` — English food name matched USDA directly (e.g., "Boiled Eggs")
- `"mapped"` — user provided a manual mapping to a generic equivalent
- `"skipped"` — user set to "skip" in mappings (Quick Add, Dessert, etc.)

**Error handling:**
- No USDA result found → log warning, mark as `"unresolved"`, skip in analysis
- API rate limit → respect 429 responses, retry with backoff
- Missing individual nutrients in USDA response → store as `null`, analyzer handles gracefully

### 3. Analyzer (`analyzer.py`)

**Input:** 
- List of `FoodEntry` dicts (from parser)
- TinyDB (enriched USDA data)
- Reference ranges config (from `reference_ranges.yaml`)

**Calculation:**
1. For each food entry, look up its USDA micro profile from TinyDB
2. Scale per-100g values: `actual_micros = per_100g × (total_weight_g / 100)`
3. Sum all food entries per day → daily totals per nutrient
4. Compute simple average across all logged days → daily average per nutrient
5. Compare daily average against reference ranges

**Status determination:**
| Condition | Status |
|-----------|--------|
| Value ≥ RDA/AI and ≤ UL (or no UL) | 🟢 **OK** |
| Value < RDA/AI but ≥ 50% of RDA/AI | 🟡 **Low** |
| Value < 50% of RDA/AI | 🔴 **Deficient** |
| Value > UL | 🟠 **High** |

**Amino acid handling:**
- Reads `body_weight_kg` from `reference_ranges.yaml` demographic section
- Computes daily target: `safe_mg_per_kg × body_weight_kg / 1000` (convert mg to g)
- Sums Methionine + Cysteine columns from food entries for the combined requirement
- Sums Phenylalanine + Tyrosine columns similarly

**Output:** `AnalysisResult` dict:
```python
{
    "period": {"start": "2026-07-13", "end": "2026-08-09", "days": 21},
    "nutrients": {
        "vitamin_a_mcg": {
            "name": "Vitamin A",
            "unit": "mcg",
            "daily_avg": 412.3,
            "target": 900,
            "target_type": "rda",
            "ul": 3000,
            "status": "low",
            "pct_of_target": 45.8,
        },
        # ... all nutrients
    },
    "coverage": {
        "total_food_entries": 223,
        "mapped_entries": 207,
        "skipped_entries": 12,
        "unresolved_entries": 4,
        "skipped_foods": ["Quick Add", "Dessert, Prepared"],
    }
}
```

## Edge Cases

| Case | Handling |
|------|----------|
| "Quick Add" entries | Skipped — no food name to look up. Logged in coverage stats |
| Vague food names ("Dessert, Prepared") | User maps to "skip" or a generic USDA equivalent |
| USDA returns no results for a food | Marked "unresolved", excluded from analysis, listed in report warnings |
| Food has `null` for a specific nutrient in USDA | That nutrient excluded from that food's contribution (not counted as 0) |
| No UL established for a nutrient | "High" status never triggered; only RDA/AI comparison |
| `body_weight_kg` not set | Amino acid section skipped with a warning |
| `food_mappings.yaml` has unmapped foods (empty string) | Enricher tries USDA search with original name first; if no result, flags as needing mapping |

## Out of Scope (v1)

- Workout analysis (future module)
- Per-day breakdown (v1 shows daily average only)
- Meal timing analysis
- Trend analysis over time
- Automatic German → English food translation
