# Store the App's Data in S3 Implementation Plan (BAR-83)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make S3 (`omni-pilot-data`, `eu-central-1`) the only home of the food database, mappings, recipes and MacroFactor exports, with `pull`/`push` commands that `analyze` and the custom-foods skill use around their work.

**Architecture:** A CDK stack in `infra/` creates the bucket and a limited IAM user. In the app, `config.load_s3_config` reads the S3 settings (settings.yaml or `OMNI_PILOT_S3_*`), `s3.py` is a hand-signed (SigV4) S3 client on `requests`, and `sync.py` moves the three data files and the exports between S3 and the device's local working copy, using a per-device `.s3_state.json` and conditional `PUT`s to refuse stale writes. `cli.py` gains `pull`/`push` and wraps `analyze` with them.

**Tech Stack:** Python 3.14, requests, PyYAML, openpyxl, TinyDB, Rich, pytest + pytest-mock, ruff; AWS CDK v2 (Python, `aws-cdk-lib`) with the `cdk` CLI already installed on the Mac.

**Spec:** `docs/specs/2026-10-18-s3-storage-design.md` (version 1.3, approved 2026-10-20). Read it first; this plan argues from it and does not repeat its reasons.

## Global Constraints

- **Pure Python app.** Nothing under `src/` may import `boto3`, `botocore` or any package with C extensions; `requirements.txt` (the iPhone install) must not change. CDK packages live only in the `infra` dependency group.
- **Secrets:** never in a URL, a log line, an exception message or a print. SigV4 goes in the `Authorization` header; no presigned URLs. Error messages name a setting or variable, never its value.
- **HTTP:** every S3 request passes `timeout=S3_TIMEOUT`, a `(connect, read)` tuple `(5, 30)`, through a module-level `requests.Session`. No retries.
- **No real S3 in tests.** Every test fakes `omni_pilot.s3._SESSION.request` (or the client). No test reads `~/.aws` or real settings.
- **Names, copied from the spec:** bucket `omni-pilot-data`, region `eu-central-1`, stack `OmniPilotData`, IAM user `omni-pilot-app`, keys `food_db.json`, `food_mappings.yaml`, `custom_foods.yaml`, `exports/<first>_<last>_<hash8>.xlsx`, state file `.s3_state.json` beside the database, env vars `OMNI_PILOT_S3_BUCKET`, `OMNI_PILOT_S3_REGION`, `OMNI_PILOT_S3_ACCESS_KEY_ID`, `OMNI_PILOT_S3_SECRET_ACCESS_KEY`.
- **Push order:** export(s) first, then `food_db.json`, `food_mappings.yaml`, `custom_foods.yaml`; the first failure stops everything after it.
- **Not configured ⇒ today's behaviour.** With no `s3` section (or `s3:` empty) and no `OMNI_PILOT_S3_*` variable set, `analyze` makes no S3 call.
- **AWS changes only with the user's go-ahead.** Claude shows `cdk diff` and waits before `cdk deploy`. The access key is created by the user, never by Claude or the stack.
- **Commits:** one concise summary line, no body: `feat: … (BAR-83)`, `test: …`, `docs: …`, `chore: …`.
- **Lint:** `uv run ruff check .` passes (`E, F, I, UP`, line length 120), `infra/` included.

## Review Focus

Inputs the spec implies but its test list does not name, most likely first. Each has a test in the task named.

1. **ETags arrive quoted** (`"9b2cf535f27731c974343645a3985328"`) → `If-Match` sends the header value exactly as S3 returned it, quotes included (Task 3).
2. **A fresh cloud clone** has no `db/`, `config/*.yaml` or `data/` folders → `pull --exports` creates the folders and fills them (Task 4, Task 5).
3. **The same export analysed twice** (the iPhone re-runs `data/data.xlsx`) → the second upload reports `already in S3`, the data files are still pushed, exit 0 (Task 7).
4. **The device clock is off** → S3 answers 403 `RequestTimeTooSkewed`; the message says the device clock is wrong instead of blaming the key (Task 3).
5. **`s3:` present but empty in settings.yaml, all values from the environment** (the cloud-session case) → configured from the variables; `s3: null` with no variables → not configured (Task 2).

- [ ] **Step 4: Implement `s3.py`**

- Signing per AWS SigV4: canonical request (method, path, sorted query with each name/value `quote(…, safe="-_.~")`, canonical headers, signed headers, payload hash) → string to sign (`AWS4-HMAC-SHA256`, date, scope `<yyyymmdd>/<region>/s3/aws4_request`, SHA-256 of canonical request) → signing key chain `AWS4+secret → date → region → "s3" → "aws4_request"` with `hmac`/`hashlib`.
- Requests: URL `https://{bucket}.s3.{region}.amazonaws.com/{quote(key, safe="/-_.~")}`; sign `host`, `x-amz-content-sha256` (SHA-256 of body), `x-amz-date` (UTC now); add `If-Match` / `If-None-Match: *` after signing (unsigned headers are allowed).
- `list`: `GET /` with `list-type=2`, `prefix`, optional `continuation-token`; parse with `xml.etree.ElementTree` (namespace `http://s3.amazonaws.com/doc/2006-03-01/`).
- Errors: read `<Code>` from the XML error body when present. 403 with `RequestTimeTooSkewed` → `other`, "S3 refused the request: this device's clock is off — set the time automatically and run again". Other 403 → `auth`, `f"S3 refused the key — check {source}"` where `source` is `"s3 in settings.yaml"` or `"the OMNI_PILOT_S3_* variables"` from `key_source`. 409 `ConditionalRequestConflict` and 412 → `conflict`, `f"{key} changed in S3 since it was downloaded"`. `requests.ConnectionError`/`Timeout` → `network`, "S3 not reachable — is the network down?". Anything else non-2xx → `other`, `f"S3 answered {status} for {key}"`. Never include headers or the request in messages.
